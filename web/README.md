# Filebonsai web client

The Library, Storage, and sign-in as a React Router 8 single-page app (Framework
Mode, SPA), built from the `react-router-spa-template` starter (version and commit in
`package.json` under `template`): React Aria-backed shadcn Nova, Tailwind 4, TanStack
Query/Form, Zod, Zustand, and Lucide. Agents start at [AGENTS.md](AGENTS.md).

```bash
nvm use                  # Node 24; minimum 22.22.0
npm ci
npm run generate:schema  # after the backend contract changes
npm run dev              # http://localhost:5173, proxying /api to the backend
npm test                 # lint, typecheck, tests, build
```

`src/lib/api/generated/schema.ts` is generated by `openapi-typescript` from
`../backend/contract/openapi.json`; never edit it. `src/lib/api` wraps it with
`openapi-fetch`: every request sends the session cookie, and the client holds the
double-submit CSRF token for state-changing calls. Callers supply stable idempotency
keys for folder creation and uploads, so a retry keeps the same intent.

The dev server proxies `/api` and the OIDC paths to the backend at
`http://127.0.0.1:8080`. Set `FILEBONSAI_API_PROXY_TARGET` for another origin, such
as `http://127.0.0.1:8081`. `VITE_` settings are validated by `src/lib/env`: set
`VITE_FILEBONSAI_OIDC=authentik` when the backend has Authentik OIDC configured to add
**Continue with Authentik** to sign-in; the local Compose stack sets it. See
[.env.example](.env.example).

`npm run build` writes static files to `build/client`; there's no Node server. Hosts
must serve `index.html` for app routes and serve assets and API paths normally.

## Behavior worth knowing

- Anonymous visitors are sent to `/sign-in`. The owner password goes through the
  CSRF-protected session API once and isn't kept; a successful sign-in clears the
  query cache.
- Uploads run in a tab-owned store (`src/lib/transfers`), so folder navigation never
  stops them. Before beginning, the store reads the server's upload limit once per tab
  and refuses larger files without sending anything, naming the limit. If the limit
  can't be read, or the server answers `413`, the server decides and the limit is read
  again. Retry reads server state first and resends from byte zero only for an
  initiated session. Uncertain completion offers a status check; it never assumes the
  original is available. Cancellation is server-confirmed and fences late replies.
  Each explicit transfer operation reads a fresh CSRF token, since the session may
  have rotated.
- Keep the tab open: selected files and transfer tracking live in memory and aren't
  restored after reload. Downloads and previews buffer the original as a Blob.
- The Storage page loads in its component, not a `clientLoader`, so it owns its
  loading, error, and unavailable states inside the shell.

## Design tokens and layout

`src/styles/index.css` holds every token: Filebonsai's palette on the shadcn roles,
plus its type scale, density and region sizes. The shell and transfer tray use
`src/lib/ui`; the other screens still use `src/styles/app.css` through the role
aliases in `src/styles/tokens.css`, and move onto `src/lib/ui` screen by screen.
`src/styles/tokens.test.ts` fails on a raw color outside `index.css` and on AA text
or 3:1 control and focus contrast regressions. The shell (`src/routes/app-shell`) shows a sidebar from 1100px,
an icon rail from 768px, and top and bottom bars below that. The folder list uses
container queries, so it adapts to its own width. Icons come from `lucide-react` (ISC
license).

Refresh or add components with `npm run ui:add -- <name>`. The pinned shadcn CLI
writes them into `src/lib/ui`. Review the code and any new dependencies, because
registry content isn't pinned.
